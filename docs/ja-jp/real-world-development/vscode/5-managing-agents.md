GitHub Copilot をエージェント モードで使うと、コードベースを調査し、変更を提案し、ファイルを編集してコマンドを実行します。作業はローカル マシンでリアルタイムに進むため、VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をその場で確認できます。diff をインラインで確認し、個々の変更を受け入れたり取り消したりして、エディターを離れずに追加のプロンプトを送信し、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッションの途中でエージェントを誘導し、ハイ コントラスト モードとともにライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者のために、ライト モードの切り替えも追加したいとのことです。最初から新しい会話を始める代わりに、既存のセッションを誘導して機能を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した変更を確認できます。各ファイル編集は diff とともにチャット内に表示され、**Keep** と **Undo** を選択できます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められているターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、diff がチャット内に表示されます。
    - **Keep** を選択して変更を受け入れます。
    - **Undo** を選択して変更を取り消し、もう一度処理するようエージェントに任せます。
4. チャット上部の **Files changed** インジケーターを開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ツール呼び出しで許可 (ターミナル コマンドの実行など) を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドのみ承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に変更内容をまとめたメッセージが表示されます。

## ライト モードを追加するようエージェントを誘導する

ハイ コントラスト モードが完成したら、同じ会話にライト モードの切り替えを追加します。同じチャット セッションを続けると、エージェントは前の作業で扱ったコンポーネント、スタイルの方法、local storage のパターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を調査してから、ライト モードの追加を提案します。
3. ハイ コントラスト モードのときと同様、変更が表示されたら確認し、それぞれ **Keep** または **Undo** を選択します。
4. エージェントの進め方が意図と異なる場合 (たとえば、希望しない方法で切り替え UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンを選択して停止し、意図を明確にするプロンプトを送信します。

> [!TIP]
> 実行中のセッションを誘導すると、最初からやり直すよりも効率的です。追加プロンプトを使って、調整を依頼できます ("CSS を簡潔にし、セレクターを重複させず CSS 変数を使う")、方向を修正できます ("3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを組み込む")、または範囲を広げられます ("両方の切り替えにキーボード ショートカットも追加する")。

## 作業内容をレビューする

コミットする前に、エージェントが変更したすべてのファイルを簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連するテストが更新されているはずです。
3. 変更されたファイルをいくつか開き、diff を確認します。アクセシビリティ用カスタム エージェントの指針 (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで実行中のセッションを監視して誘導しました。ファイルの編集を確認しながら受け入れるか取り消し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり取り消したりしました。
- 追加プロンプトを使って、進行中のセッションを誘導しました。

[次のレッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが作成した変更を確認します。
